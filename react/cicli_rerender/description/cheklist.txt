## Checklist do Fantasy Draft App

### Etapa 1: Tipagem e Contratos (`types.ts`)

* [ ] `interface Player` contendo: `id` (string), `name` (string), `position` (string), `price` (number) e `isDrafted?: boolean`.
* [ ] Interface Genérica `ApiResponse<T>` contendo: `data: T`, `status: number`, `message?: string`.
* [ ] Interface/Type `ApiError` contendo: `message: string`.
* [ ] Type Guard `isApiError(error: unknown): error is ApiError` utilizando os operadores `in` e `typeof`.

---

### Etapa 2: Camada de Dados & Custom Hook (`usePlayers.ts`)

* [ ] Mock de dados com pelo menos 6 a 8 jogadores tipados como `Player[]`.
* [ ] Estados do Hook: `players` (`Player[]`), `loading` (`boolean`), `error` (`string | null`).
* [ ] `useEffect` simulando chamada HTTP com `Promise` + `setTimeout` (1.5 segundos).
* [ ] Bloco `try/catch/finally` utilizando o Type Guard `isApiError` para capturar exceções.
* [ ] Retorno do hook: `{ players, loading, error }`.

---

### Etapa 3: Componente Leaf Memorizado (`PlayerCard.tsx`)

* [ ] Interface `PlayerCardProps` tipando as props: `player` (`Player`), `isDrafted` (`boolean`), `onToggleDraft` (`(id: string) => void`).
* [ ] Inclusão de `console.log(`[RENDER] PlayerCard: ${player.name}`)` no topo do componente para monitorar re-renders.
* [ ] Layout do Card: Nome do jogador, posição, valor do contrato e botão dinâmico ("Contratar" / "Dispensar").
* [ ] Export do componente envelopado com `React.memo`.

---

### Etapa 4: Tela Principal & Performance (`App.tsx`)

* [ ] Consumo do Custom Hook: `const { players, loading, error } = usePlayers()`.
* [ ] Estado local `search` (string) conectado ao `TextInput`.
* [ ] Estado local `myTeam` (`string[]`) guardando os IDs dos jogadores contratados.
* [ ] `useMemo` para `filteredPlayers`: filtrando a lista por nome com `.filter()`.
* [ ] `useMemo` para `totalCost`: calculando o custo total do time atual com `.reduce()`.
* [ ] `useCallback` para a função `handleToggleDraft`: alterando o estado `myTeam` com atualização funcional (`prev => ...`) e Spread Operator.
* [ ] Header com o Painel do GM (Total de contratados e Folha Salarial).
* [ ] Renderização da lista através do `FlatList`.

---

### Etapa 5: Validação e Regra de Ouro da Performance

* [ ] **Zero `any`:** Nenhum arquivo possui o tipo `any`.
* [ ] **O Teste de Ouro:** Ao abrir o app e digitar qualquer texto no campo de busca, os cards que continuam na tela **não exibem** novos logs de `[RENDER]` no console.
